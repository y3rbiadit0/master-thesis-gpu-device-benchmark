\frontchapter{Abstract}
Communication can limit the performance of applications using Graphics Processing Units (GPUs) both within a compute node and across a cluster. Choosing a communication stack requires understanding how message size, communication structure, and synchronization interact with the underlying interconnect. This thesis investigates when GPU-initiated communication benefits distributed applications, how portable interfaces preserve or alter those benefits, and which benchmark findings transfer to a complete Conjugate Gradient (CG) solver.

The evaluation follows a bottom-up approach on Leonardo Booster, using up to 32 NVIDIA A100 GPUs across eight nodes. A unified CUDA/SYCL benchmark suite compares MPI, NCCL, oneCCL, NVSHMEM, and OSHMPI through point-to-point transfers, neighbor exchanges, reductions, and redistribution, followed by mixture-of-experts communication and a composite CG iteration. Complete \texttt{aCG} solver experiments on two large sparse matrices then test the application relevance of these measurements. Software contributions include grouped NCCL point-to-point support and an OSHMPI backend for oneCCL, a validated NVSHMEM backend foundation, and extensions to \texttt{aCG} providing an OSHMPI communicator and a SYCL implementation.

The results show that scaling up within a node and scaling out across nodes favor different communication paths. MPI performs well for small messages and isolated exchanges, while NCCL-based paths lead bulk multi-node collectives. Persistent GPU-initiated NVSHMEM achieves approximately 41\,GB/s of aggregate logical halo bandwidth across two to eight nodes, compared with approximately 34--36\,GB/s for MPI. This advantage is specific to sustained, batched neighbor exchanges: intra-node competitiveness does not generally carry over to scale-out execution under the evaluated CPU-proxy-assisted NVSHMEM networking. Payload distribution also changes the outcome, with routing-dependent redistribution reversing rankings observed for uniform all-to-all communication.

In \texttt{aCG}, matched scalar-reduction costs show close agreement with benchmark measurements, whereas irregular neighbors and computation--communication overlap prevent isolated halo rankings from predicting solver performance. The SYCL implementation provides a concrete performance-portability case study: within a node, it takes 0.87--1.02 times the native CUDA solver time, and its MPI variant continues strong-scaling to 32 GPUs. Across nodes, host-synchronous oneCCL reductions introduce additional waiting, highlighting the importance of completion semantics when preserving performance through a portable interface.

Overall, effective backend selection requires matching communication patterns, execution dependencies, and topology to the application. The results demonstrate that a portable solver can retain native performance on the evaluated NVIDIA platform, while the benefits of GPU initiation depend on the communication schedule and transport.
